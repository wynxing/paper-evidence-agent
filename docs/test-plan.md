句子标记见 [术语表](glossary.md)。本文是路径一的测试方案。被测对象是 [产品需求](prd.md) 里的 paper agent。测试执行者是仓库外的成熟 agent，例如 Claude、Cursor。本仓库提供被测应用、可复现用例、诊断包和轨迹，不提供评审实现，也不把这些外部 agent 写成依赖。

本文不是路径二的测试平台，也不是 [研究评测](evaluation.md)。研究数据集不得被运行时导入，也不得用来宣告本节用例通过。

被测模块的目录见 [架构设计的代码布局](architecture.md#代码布局)。诊断包字段和外部评审的返回结构只以 [术语表](glossary.md#6-诊断包) 为准。

## 1. 外部评审怎么做

**规则**：路径一的评审不在本仓库里实现。Claude、Cursor 等外部 agent 运行下面的用例，或阅读对应的执行记录、诊断包和轨迹，然后按术语表的返回结构写下观察、引用和根因假设。`confirmed` 只在复现步骤或确定性校验成立时使用。只有模型解释时必须写 `suspected`。

外部评审默认只读，不修改论文、仓库、任务或来源缓存，也不把不同意的标签回写成新的任务状态。未发表论断和完整语义包须作者另行同意后才能交给它们。

至少留下四类记录：

- 用例：每个维度至少覆盖下面写出的判定，并写明前置条件和期望终态。
- 执行结果：命令或界面步骤、实际状态、结果标签和错误码。
- 诊断包：失败和阻断的任务要能导出输入诊断包。
- 缺陷分析：外部评审的返回值。写明已观察到的异常、可能根因，以及仍须复现的部分。

### 自动归因的最小执行闭环

外部测试 Agent 由测试负责人在仓库外启动，固定输入为 case_id/run_id/trace_id、只读数据入口及用例预期。按以下步骤执行，不把“接入 Langfuse”本身写成自动归因完成：

1. 通过授权的本地诊断包与轨迹读取任务；启用 Langfuse 时可按 trace_id 取回同一条脱敏轨迹。取数失败必须明确返回诊断证据不足，不能伪称看到了完整链路。
2. 关联 execution、model_calls 与原文位置，输出术语表规定的结构化报告；每条 findings 引用实际存在的 span/字段/段落。无语义授权时只诊断流程，不声称判断论断真假。
3. 在隔离测试夹具上执行允许的只读复现/确定性检查，记录命令与结果；只有这些证据支持才能 confirmed，否则 suspected 或 insufficient_evidence。
4. 评测器用隐藏的注入真因核对归因、引用和复现断言。注入覆盖检索异常、限流、总超时、摘录错配等；报告有效率及无法归因项，不将注入真因交给 Agent。

自动化的是上述取数、分析、报告链路；归因报告不修改应用状态、不自动修代码。保留输入版本、Agent 配置、工具调用、耗时、成本和输出；未实际跑通前仅为设计要求。

## 2. 维度

### 功能准确性

- 目录：`tests/functional/`，冻结样本及预期只供测试读取，运行时不得导入。
- 确定性判定：多条 evidence 均须定位到同一冻结版本；结构、身份、许可或任一摘录校验失败时不展示确定判断。quote 存在并不证明 label 正确。
- 语义验收：制作小规模真实 PMC 来源集，人工核对 DOI、版本、许可、原文位置和预期判断。覆盖支持、部分支持、相矛盾、证据不足，以及对象、数量、条件、因果关系、否定方向的变化，每种至少一例；同一例可覆盖多个维度。构造的论断变体须标明是构造输入，不冒充自然引文。
- 验收器负向控制：在已人工核对的正确结果上，故意换为语义明确错误的标签或不匹配摘录，验收器必须检出错误；正确对照也须通过，防止永远拒判。邻段可能同样支持论断，不能仅因更换邻段就硬设失败。控制不通过时不得用该验收器发布语义成绩。
- 标注：一人整理，另一人复核；分歧解决前不计为确定真值。保存依据和限制；无法支持预期标签的样本不得硬设答案。外部 Agent 可协助整理，但不能自评为真值。
- 通过条件：冻结首版验收集逐例满足人工核对的标签及关键语义约束；应可判定的样本不能全部以证据不足通过。未通过时报告具体错例并修复，不删除失败用例以改变结果。该条件仅限有限验收集，不是总体准确率保证。
- 采样与分母使用 [评测口径](evaluation.md#4-质量指标)，首版 n=1 单次抽样不声称标签稳定。
- 报告：分别给出摘录定位有效率、语义标签/关键约束的正确数与总数、可判定覆盖率、样本类别分布。摘录指标没有确定判断时写“不适用”，不能写 100%。另列误判与过度拒判，不只报条件准确率。各学术标签给出 TP/FP/FN、真实样本数与预测数，以及 precision=TP/(TP+FP)、recall=TP/(TP+FN)；单列相矛盾类。分母为零写 N/A，不补成 0 或 100%。拒判及执行失败不能从召回率分母移除；自然未完成与人工取消的测试单列，不能用取消逃避质量验收。
- 不测：不以 SciFact 摘要成绩、模拟输出或一次演示替代真实全文语义测试；120 对正式研究集不是前置条件。

### 工具调用

- 目录：`tests/tools/`，覆盖 sources、models、api 和 graph。
- 未确认来源、云调用或主接收方时不入队、不调用模型；配置预览已过期时返回 409，重新确认后才能创建。
- 用本地可控上游验证应用请求确实经过 Proxy；断开 Proxy 后不得偷偷直连供应商。只改别名映射即可切换测试上游，不改业务代码。
- 验证 429 后恢复成功及耗尽后 UPSTREAM_RATE_LIMITED、超时恢复仍失败为 UPSTREAM_TIMEOUT、连接/暂时性服务错误恢复耗尽为 UPSTREAM_UNAVAILABLE、认证失败 UPSTREAM_AUTH_FAILED 和参数错误 UPSTREAM_INVALID_REQUEST 不重试；最多首次加一次恢复，客户端不再重试。
- 日常模式备用调用占用同一恢复槽位，不允许先重试再回退；未授权接收方不得收到请求。不得因“证据不足”或内容拒绝切换模型。
- evaluation 别名固定单部署，跨模型/部署回退与模型响应缓存关闭；同样输入发出真实请求，不因缓存导致计数伪少。
- 来源连接器仅访问官方只读端点，其恢复与模型预算分别记录；接口报错不能伪装成来源不存在。
- 使用可控网关元数据验证每次失败和成功尝试都关联 request_id；只有最终响应不算尝试记录完整。真实上游接入另列结果，模拟通过不代表 Agnes 已联通。

### RAG

- 目录：`tests/retrieval/`，覆盖切分、FTS5、补读和实际模型上下文。
- 只检索当前冻结来源，拒绝跨来源段落 ID、URL/路径以及可执行 SQL。候选去重，逐请求记录 context_paragraph_ids，不能只记录全任务 entered_context。
- 覆盖中文论断与英文正文、同义改写、首次为空但补充查询找到证据、邻居段落揭示适用条件、补充检索仍为空。
- 初次检索为空不得直接结束；补充仍空时 COMPLETED/证据不足/RETRIEVAL_EMPTY。上游请求失败不能替换成这个结果。
- 检索输入覆盖裸引号、未闭合括号、AND/OR/NOT、NEAR(、冒号、星号和空白/标点输入。合法普通词编译后不得成为 MATCH 操作符；数据库/索引故障返回 RETRIEVAL_FAILED，不能消耗输出修复次数或变成 RETRIEVAL_EMPTY。
- 使用 unicode61 验证中文词汇在连续中文正文的子词召回盲区；“中文论断→英文正文”受支持，“英文论断→中文正文”须 SOURCE_LANGUAGE_UNSUPPORTED。英文摘要配中文正文、语言声明与实际正文不符也不得冒充英文来源成功。
- 冻结同一 JATS 与解析器两次解析须产生相同 ID/文本/哈希；替换版本、重排段落、改变解析器后旧 ID 不得指向新段落。跨 PMCID 同序号不得碰撞，缺失旧快照须明确不可复现。精确匹配覆盖空白展开、大小写/引号差异和重复摘录位置。
- 在真实来源标注段落上报告 Recall@k 及遗漏原因。测试数据与 k/上下文限制版本化；是否引入嵌入检索由这些遗漏支持，首版不增加向量数据库。

### 任务内澄清、隔离与多步执行

- 目录：`tests/session/`，覆盖任务输入、授权快照、graph 和模型客户端。
- 默认路径：查询生成 → 检索 → 判断；补读路径最多增加一轮检索和一次最终判断。不为了单 Agent 限制而禁止多步调用。
- 同一任务最多三个主请求加一个全局修复请求，每个最多两次上游尝试，整任务最多八次。分别验证查询生成修复、判断修复、伪造摘录修复、修复仍失败，以及修复后不重置预算。
- 请求 3 输出 retrieve：修复槽位尚在时只用已有材料修成 final，不执行工具；修复槽位用尽或修复仍错时 MODEL_INVALID_OUTPUT。合法动作超过额度时在派发前 BUDGET_EXCEEDED。分别验证这三支互斥、取消/总超时优先、最大 3+1 请求不变。修复后的摘录仍须逐条重新验证。一次修复输入包含当前响应全部可检测错误；前一步用完修复、后一步再次出错应失败，不暗增修复预算。
- 上一条论断不得进入下一条任务；重试新建任务，重新确认当前配置与授权，不静默沿用已扩大的接收方名单。历史仅在界面和存储可见。
- 覆盖多主张输入返回拆分提示，作者改写或拆分后重新确认提交；每个新任务使用 previous_id 关联，但模型上下文不继承原任务。运行中修改不得覆盖旧输入；拒绝授权保持草稿且零模型请求，重新确认后才创建任务。进度始终关联各自任务 ID。
- 这些是任务内澄清、隔离及多步工作流测试，不声称支持通用多轮聊天。

### 对抗与安全

- 目录：`tests/adversarial/`
- 被测模块：`graph/` 对不可信输入的处理，以及 `sources/` 的端点限制。
- 判定：来源文本、网页和工具返回中的指令不得改变任务目标，不得让模型指定任意网址，也不得让连接器离开官方只读端点。
- 在正常、失败和重试路径注入测试用敏感标记，扫描应用/Proxy stdout、日志文件、异常与回调载荷及 redacted 导出；原句、查询、提示词、模型响应和密钥不得泄漏。理由及限制字段也不能绕过脱敏。
- semantic export 的本地预览和接收方授权与模型调用分开；未授权时不生成 consented 导出，生成后不自动外传。
- redacted 导出保留公开 DOI、PMCID、题名及章节，但预览必须明确书目身份仍可见；来源字段来自公开原文，不接受模型生成文本冒充公开书目。测试不应错误要求 redacted 隐藏已明确保留的书目，也不得声称其主题匿名。
- Langfuse 默认关闭时零网络导出；未授权、配置缺失均不启用。启用后的故障不改变核验状态、不增加业务重试，脱敏回调不得带出原句/响应。
- 不测：不把仓库做成通用越狱研究平台。

### 边界与异常

- 目录：`tests/boundary/`
- 被测模块：`domain/` 的错误码和任务状态，由 `graph/` 写入 `storage/`。
- 按 [全部错误码](glossary.md#4-错误码) 各覆盖至少一个终态用例；特别区分身份错配 SOURCE_MISMATCH、无来源、许可未知、许可已知但暂不支持、内容缺失，以及网络失败；摘录不匹配且修复仍失败为 QUOTE_MISMATCH。
- 验证脱敏 schema 2.2 包的字段和 JSON 形状；请求/尝试/证据关联可追溯，FAILED/BLOCKED/INTERRUPTED/CANCELLED 的 decision 为 null。缺失 usage 和不可验证模型版本为 null，不能写零或别名。
- 逐次元数据缺失但路由/预算控制可靠时，保留有效学术结果，accounting=unverified、实际尝试数为 null 且展示已记录下界；不得把未知 usage 当作零或调用账不完整。模拟控制失效须停止后续调用，不能按仅缺元数据放行。
- 配置/判据摘要测试：键顺序不同摘要相同，字符串空白和数组顺序变化摘要不同；运行计数不影响摘要，判据语义和有效配置变化必须改变相应摘要；旧快照可按引用取回。
- 普通重启发现无取消标记的 RUNNING → INTERRUPTED，保留诊断且标签为空；重试新建任务，不静默重发。与有取消标记的 CANCELLED 分支分别断言。
- DOI 用例覆盖格式错误、Crossref 404 但机构确认 Crossref、有效非 Crossref DOI、机构未找到但官方解析成功、官方明确未找到，以及网络超时；断言 HTTP 状态和独立错误码。未创建任务的预览错误不得伪造 BLOCKED 任务，已入队后来源重查失败才落对应终态。
- 取消覆盖 QUEUED、RUNNING、重复请求、取消先于完成、完成先于取消、总超时与取消竞争、重启发现持久化取消标记，以及迟到上游响应不覆写终态。核对取消后无新尝试，保留已发生费用未知的说明。
- 多证据判定中任意一条摘录无效均须阻止确定判断；有真实摘录但语义关系错误由功能语义集检出，不能用定位测试替代。
- 不把这些错误统一写成“引用不支持”；每个已恢复错误仍保留在尝试记录，不覆盖最终成功结果。

### 性能

- 目录：`tests/performance/`
- 被测模块：`worker/`。
- 判定：保持单进程、一次一个任务。记录单任务延迟、逻辑请求数、上游尝试数及 token（缺失标为未知）。再提交任务时，后来的任务停留在 `QUEUED`，不另起执行器。
- 受控验收：45 秒模型尝试、15 秒来源请求、180 秒总执行时限；用虚拟时钟检查超时边界，实际本机无负载集成检查取消接口 1 秒内响应、受理后 2 秒内收尾释放 worker，deadline 后 2 秒内收尾。失败须报告具体测量，不能仅记录不判断。
- 总时限从 RUNNING 开始，含解析/重试等待、不含队列。验证剩余时间截短单次超时、Retry-After 大于剩余时间不再发起重试，以及取消中断退避。总时限先到时不要求耗完全部调用次数；观测导出不可拖延释放 worker。
- 不测：不引入 Redis、Locust、JMeter 或分布式压测。

界面主路径放在 `tests/e2e/`，用 Playwright 覆盖确认来源、同意整次任务的接收方、数据范围与预算、查看 paper agent 的判断与原文位置，以及澄清重提、取消排队/运行任务、显示超时与书目导出预览、删除本地记录。它不替代上面各维的判定。外部评审可以运行这些用例，但界面测试本身不调用 Claude 或 Cursor。

## 3. 与研究评测的分界

**排除**：120 对正式集规模、SciFact 和大规模跨模型对照属于后续研究，不作为首版用例通过的前置条件。首版小规模人工核对语义集属于本方案，不因研究后置而省略。所有测试及研究真值数据都不能被 `backend/paper_evidence/` 导入。

## 4. 执行记录与当前边界

每次记录文档/代码提交、环境、命令、配置及来源快照摘要、实际结果和失败项。区分纯单元测试、模拟上游的 Proxy 集成、真实模型连通性、真实论文语义验收和正式研究。

当前仓库有设计文档，没有应用、应用测试套件或冻结语义集。固定验证记录见 [verification.md](verification.md)，须含验证对象提交/工作树基线、环境、命令、实际结果及未覆盖项；缺失结果即未验证。文档差异可作静态检查，但不代表应用、模型、性能或真实论文测试通过；以上未来测试均尚未执行。
