状态：设计稿

日期：2026-09-27  
作者：Wynn  
读者：实现与参赛测试  
相关文档：[术语表](glossary.md)、[产品需求](prd.md)、[架构设计](architecture.md)、[技术选型](tech-stack.md)

句子标记见 [术语表](glossary.md)。本文是路径一的测试方案。被测对象是 [产品需求](prd.md) 里的 paper agent。测试执行者是仓库外的成熟 agent，例如 Claude、Cursor。本仓库提供被测应用、可复现用例、诊断包和轨迹，不提供评审实现，也不把这些外部 agent 写成依赖。

本文不是路径二的测试平台，也不是 [研究评测](evaluation.md)。研究数据集不得被运行时导入，也不得用来宣告本节用例通过。

被测模块的目录见 [架构设计的代码布局](architecture.md#代码布局)。诊断包字段和外部评审的返回结构只以 [术语表](glossary.md#6-诊断包) 为准。

## 1. 外部评审怎么做

**规则**：路径一的评审不在本仓库里实现。Claude、Cursor 等外部 agent 运行下面的用例，或阅读对应的执行记录、诊断包和轨迹，然后按术语表的返回结构写下观察、引用和根因假设。`confirmed` 只在复现步骤或确定性校验成立时使用。只有模型解释时必须写 `suspected`。

外部评审默认只读，不修改论文、仓库、任务或来源缓存，也不把不同意的标签回写成新的任务状态。未发表论断和完整语义包须作者另行同意后才能交给它们。

至少留下四类记录：

- 用例：每个维度至少覆盖下面写出的判定，并写明前置条件和期望终态。
- 执行结果：命令或界面步骤、实际状态、结果标签和错误码。
- 诊断包：失败和阻断的任务要能导出输入诊断包。
- 缺陷分析：外部评审的返回值。写明已观察到的异常、可能根因，以及仍须复现的部分。

## 2. 维度

### 功能准确性

- 目录：`tests/functional/`
- 被测模块：`domain/`，以及 `graph/` 写回的标签。
- 判定：冻结夹具上的确定判断必须能定位摘录，且摘录在同版本段落中逐字出现。身份、许可或摘录失败时不展示确定判断。
- 不测：不用 SciFact 或其他摘要语料的分数充当本节通过。paper agent 的标签不是客观真值。外部评审的不同意见只写入缺陷分析。

### 工具调用

- 目录：`tests/tools/`
- 被测模块：`sources/`、`api/`、`graph/`。
- 判定：作者未同时确认来源和云调用时，不创建任务，也不调用模型。连接器只访问官方只读端点。失败留下术语表中的错误码，而不是一段无法区分的“不支持”。
- 不测：不测模型自由选择工具，也不测任意网址抓取。

### RAG

- 目录：`tests/retrieval/`
- 被测模块：`retrieval/`、`storage/` 的 FTS5，以及进入模型上下文的候选标记。
- 判定：只检索当前这篇被引文献。用例检查召回段落和 `entered_context`。摘录必须来自已保存段落。
- 不测：不加向量库，也不用全库语义搜索充当本节。

### 多轮对话

- 目录：`tests/session/`
- 被测模块：`api/` 的任务隔离，以及 `agents/` 收到的输入。
- 判定：产品保持单条论断、单次任务。上一条论断不得进入下一条任务的提示词。本地历史只在界面和存储中可见。
- 不测：不把产品改成多轮对话顾问，也不为了本维度增加聊天记忆。

### 对抗与安全

- 目录：`tests/adversarial/`
- 被测模块：`graph/` 对不可信输入的处理，以及 `sources/` 的端点限制。
- 判定：来源文本、网页和工具返回中的指令不得改变任务目标，不得让模型指定任意网址，也不得让连接器离开官方只读端点。
- 不测：不把仓库做成通用越狱研究平台。

### 边界与异常

- 目录：`tests/boundary/`
- 被测模块：`domain/` 的错误码和任务状态，由 `graph/` 写入 `storage/`。
- 判定：`SOURCE_MISMATCH`、`LICENSE_UNKNOWN`、`CONTENT_INCOMPLETE`、`RETRIEVAL_EMPTY`、`UPSTREAM_TIMEOUT`、`MODEL_INVALID_OUTPUT`、`QUOTE_MISMATCH` 各至少一条失败或阶段用例。终态和结果标签与术语表一致。`RETRIEVAL_EMPTY` 本身不把任务设为 `BLOCKED`。
- 不测：不把这些错误统一写成“引用不支持”。

### 性能

- 目录：`tests/performance/`
- 被测模块：`worker/`。
- 判定：保持单进程、一次一个任务。记录单任务延迟和 token。再提交任务时，后来的任务停留在 `QUEUED`，不另起执行器。
- 不测：不引入 Redis、Locust、JMeter 或分布式压测。

界面主路径放在 `tests/e2e/`，用 Playwright 覆盖确认来源、同意这一次云调用、查看 paper agent 的判断与原文位置，以及删除本地记录。它不替代上面各维的判定。外部评审可以运行这些用例，但界面测试本身不调用 Claude 或 Cursor。

## 3. 与研究评测的分界

**排除**：正式集规模、SciFact、人工真值和跨模型对照属于研究评测。它们可以稍后进行，但不能作为本节用例的通过条件，也不能被 `backend/paper_evidence/` 导入。
